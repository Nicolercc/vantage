## Problem

Vantage briefs only conflicts. The writer prompt (`src/brief/prompt.ts`) sets `inScope: false` for anything else and the client shows "We couldn't find a conflict to brief". The owner typed "usa airlines outage" and got that page. They want any news topic to work.

What is already topic-agnostic: quote checks (`support.ts`), the verifier (`verify.ts`), source provenance, the claim contract, the glossary and the 30-second orientation layer. What assumes a war: the writer prompt and its schema (alignment enums, escalation risk, casualty data, strike/negotiation event types), the orientation prompt, retrieval (19 world-news feeds and a headline matcher that needs every distinctive word), and UI copy.

## Premises (auto-accepted)

1. One verification pipeline for every topic. Sourced claims keep the same quote and verifier checks; only the background fields differ by topic.
2. Conflict briefs must not get worse. The conflict writer prompt stays byte-for-byte the same, and the eval thresholds stay where they are.
3. Decline only what is not news (recipes, homework, product advice, chit-chat). Sport and culture are news.
4. A cheap classification before the writer is worth it: the orientation call already runs during retrieval and finishes first, so asking it for a type costs no wall time.
5. Old stored briefs must keep loading. Contract changes add optional fields; nothing required is added.

## Approaches considered

- **A. Minimal: loosen the existing prompt.** Let the conflict prompt accept any news and keep its schema. Smallest diff, but airline outages get "alignment: State Media" perspectives and an escalation risk. Rejected: wrong content for most topics.
- **B. Classify first, two writer prompts, core plus optional modules (chosen).** Orientation returns `topicType`. Conflict topics use today's prompt unchanged. Every other type uses a general prompt with a shared core and optional modules. Retrieval gains topic desks and a scored matcher. Medium effort, low risk to conflict briefs.
- **C. One unified prompt with conditional modules, conflict included.** Cleanest long term, but rewrites the conflict prompt and risks the eval scores the project has spent weeks earning. Revisit once B has eval history for both paths.

## Recommended approach (B)

### 1. Classify first

- Orientation's JSON schema adds `topicType`: `conflict | politics | business | technology | science_health | disaster | society | not_news`. `society` covers culture and sport. Contract: `Orientation.topicType` optional (old briefs lack it).
- Orientation prompt drops "explain the conflict" for "explain the story". `inScope` stays and is derived: `topicType !== "not_news"`.
- Brief gains optional `topicType`. Missing means `conflict` (every stored brief so far).
- Writer choice: `conflict` uses `SYSTEM_PROMPT` as today; any other news type uses `GENERAL_PROMPT`. `not_news` skips the writer and verifier entirely and stores an out-of-scope brief, so a declined topic costs one small call.
- Orientation unavailable (timeout or error): use the conflict prompt as today; if it answers `inScope: false`, try the general prompt once. Conflict behaviour on failure is exactly today's; news topics still get a brief.
- The not-news page: friendly copy ("Vantage briefs news stories. Try one of these.") with the quick topics, and the trending list once `feat/trending-today` lands.

### 2. One core brief, optional modules

Core for every topic (all existing fields where they already fit): headline, orientation, summary, key facts with checked quotes, coverage comparison, sources, timeline (`relatedEvents`), glossary, location, `historicalContext` (shown as background), `keyQuestion`.

New optional core fields:
- `stakeholders`: `[{ name, role, stance }]`, 2-6 items. Generic "who's involved" for non-conflict topics. Background, unsourced.
- `whyItMatters`: string, 1-2 sentences for ordinary readers.

Conflict module = the existing top-level fields: `perspectives`, `escalationRisk`, `escalationReason`, `affectedPopulation`, `casualtyData`. They become optional in the contract (still required by the conflict writer path and always present on old briefs).

New optional `modules` object, each member nullable:
- `business`: `{ companies: string[], marketEffect: string }`
- `disaster`: `{ affectedAreas: string[], officialGuidance: string }`
- `outage`: `{ servicesAffected: string[], status: string }`

Module text is background unless it repeats a sourced claim. The general prompt tells the model to fill a module only when it clearly applies and to leave it null otherwise.

`RelatedEvent.type` enum adds `incident`, `announcement`, `decision`, `other` (additive, old briefs valid).

### 3. Retrieval

- `topicMatcher` moves from all-anchors-AND to scored matching: light stemming (plural, -ing, -ed, possessive), a small synonym table (usa/us/united states/american, airline/carrier, outage/down/disruption, ...), and a pass rule of `matched >= ceil(0.6 * anchors)`. With one or two anchors this is still "all", so conflict topics match exactly as today. Compound-place and roundup rules stay.
- Topic desks: add business, technology, science/health and US national feeds from several countries. All desks are fetched for every brief (cached 10 minutes like today), and the matcher decides relevance. Fetching by type would make retrieval wait on orientation; the cache makes the extra requests nearly free.
- News search (Bing News RSS) already takes any query and carries long-tail topics. Per-outlet cap and country round-robin in `selectNews` are unchanged.

### 4. Map only when geography matters

"Where this is" shows for conflict briefs as today. For other types it shows only when the brief has a confirmed pin or a located timeline event; otherwise the section is left out, along with the waiting-screen map card.

### 5. Copy

Functional copy changes ("We couldn't find a conflict to brief", loader tips about casualty counts, "How each side sees it" for stakeholders). The tagline "conflict, in context" and the footer "Conflict intelligence in context" stay until the owner picks. Options: keep it; "the news, in context"; "world news, in context"; "every story, in context".

### 6. Eval

- New topics, one or two per type, including "usa airlines outage", each with an expected `topicType` and expected facts drafted from recorded headlines (pending owner review with `eval:review`).
- "Premier League transfer news" moves from out of scope to in scope (`society`); recipe, phone review and Python stay out of scope as `not_news`.
- The runner classifies each case with the same orientation call, so the eval measures classification too. Type accuracy is reported; no new threshold until there is run history.
- Recording sources is network only. Running the eval spends model tokens and needs the owner's OK.

## Amendments after review (supersede the sections above)

1. **Time-sensitive module fields are checked claims.** `business.marketEffect`, `disaster.officialGuidance` and `outage.status` are `Claim[]`, run through the same quote checks and verifier as key facts. Only name lists (`companies`, `affectedAreas`, `servicesAffected`) are background.
2. **No top-level `whyItMatters`.** Orientation already carries it. `actors` stays required for every brief; `stakeholders` (name, role, stance) is the background layer behind it. The page shows stakeholders when present, else the parties list.
3. **Two server validators.** The stored/wire schema makes the conflict fields optional; generation parses conflict output with `ConflictBrief` (conflict fields required) and general output with `GeneralBrief` (stakeholders required). Test: a conflict answer missing `perspectives` is rejected.
4. **Client guards ship with the contract change.** Optional conflict fields, null guards in `adapter.ts` and `BriefView.tsx` (assessment, perspectives and people-affected sections hide when absent), neutral map and timeline handling for the new event types: all in the contract PR, before any server path produces a general brief.
5. **Routing.** Orientation is told: armed violence, military or militant action, or a crisis caused by them is `conflict` even when it is also politics. After retrieval, `buildBrief` waits for orientation for at most 2 s more (bounded by orientation's own timeout), then decides the route once. Orientation unavailable or without a type: the conflict prompt, exactly as today, including its decline. No general fallback, so no extra writer call, no deadline change, and `intelligence.test.ts` keeps its one-writer-call assertion.
6. **Declining.** `not_news` declines without a writer only for a typed topic (never a supplied article) and only when retrieval found fewer than 2 news sources; otherwise the general writer runs and may itself decline. The decline brief is built explicitly (orientation strings can be empty) and stored with `topicType: "not_news"`.
7. **Stale declines.** `briefFor` ignores a stored brief with `inScope: false` and no `topicType` (every decline saved before this change), so "usa airlines outage" regenerates. `upgradeStoredBrief` leaves `topicType` unset on old briefs; the client treats missing as conflict only when `inScope` is true.
8. **Saved decline links.** `StoredBriefRoute` renders the same decline notice as the generate route when `inScope` is false.
9. **Matcher.** The conflict vocabulary filter runs on unstemmed words; stemming only touches words of 5+ letters; "US", "UK", "EU", "UN", "AI" match case-sensitively in headlines; no loose synonyms (no "down", "disruption"); a compound place the reader asked for ("South Sudan") is one anchor, so "South Sudan floods" needs both the place and floods. Partial matches (3+ anchors) rank after full ones before outlet caps. Raw-headline fixture tests cover conflict and general topics with negatives ("Join us", "US stocks down", "US airlines announce new routes" ranked after full matches).
10. **Desk feeds** live in the same `FEEDS` array (the test harness stubs by that list) and carry a `desk` tag.
11. **Eval.** `generateFromCoverage` takes the route (`topicType`), and the runner classifies each case with the production orientation call. Existing limits are computed over the conflict cohort only; news cases and type accuracy are reported separately; a conflict case routed to the general writer fails scope. `record.ts` gets `--only` so conflict snapshots are never re-recorded. A digest test pins `SYSTEM_PROMPT`.
12. **Waiting screen.** Its map card keeps today's rule (only when the request text names a known country). The finished-brief rule: non-conflict briefs show "Where this is" and "Show on map" only with a confirmed pin or located event.
